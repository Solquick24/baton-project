## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 동행하는 가족이 진료 맥락 이어받기 (Priority: P1)

보호자 B는 동행 범위로 로그인해 같은 진료과의 지난 기록에서 바뀐 점과 가족 질문을 확인한다.

**Why this priority**: 바통의 핵심인 진료 인수인계를 독립적으로 시연한다.

**Independent Test**: 저장된 지난 기록·브리핑·질문으로 B가 변경과 질문을 보고 A가 전체 내용에서 근거를 확인한다.

**Acceptance Scenarios**:

1. **Given** 내과 1·2월과 정형외과 기록, **When** B가 3월 내과 브리핑을 열음, **Then** 내과 맥락의 바뀐 점·질문만 보이고 다른 과 기록·변경 이유·원문·인용은 없다.
2. **Given** 가족 질문 3개, **When** 통합함, **Then** 유사 질문 2개를 합쳐 통합 질문 2개와 근거 기반 추가 질문 1개를 제공하고 원 질문 관계를 보존한다.
3. **Given** 금식 여부에 근거가 없음, **When** A가 전체 내용의 준비사항을 봄, **Then** 값은 비어 있고 확인 필요로 표시된다. B에게 준비사항은 제공하지 않는다.
4. **Given** 저장된 브리핑, **When** 여러 번 읽거나 범위를 바꿈, **Then** 정보는 허용 범위대로 바뀌고 읽기 때문에 AI를 다시 호출하지 않는다.

### User Story 2 - 가족별 공개 범위 변경과 기록 확인 (Priority: P1)

환자는 B와 C의 공개 범위를 변경하고 누가 언제 무엇을 바꿨는지 확인한다.

**Why this priority**: 인수인계와 함께 핵심 시연 경로인 환자의 공개 통제를 검증한다.

**Independent Test**: 저장된 한 진료를 세 범위로 조회하고 환자 계정으로 변경 후 B의 다음 조회를 대조한다.

**Acceptance Scenarios**:

1. **Given** C는 일정만, **When** 기록을 조회함, **Then** 허용된 공통 일정 정보와 일정 블록만 있고 다른 블록 키·진료 내용·개수는 없다.
2. **Given** B는 동행, **When** 기록·홈·작업 결과·원문 경로에 접근함, **Then** 일정·동행 정보만 받고 전체 내용과 원문·인용·근거 위치는 전달되지 않는다.
3. **Given** 환자 계정, **When** B의 범위를 변경함, **Then** 다음 조회에 바로 반영되고 이전·새 범위·변경자·시각이 기록된다. AI 재생성은 없다.
4. **Given** 일반 보호자 또는 위임이 꺼진 A, **When** 공개 범위 변경을 요청함, **Then** 거부된다.
5. **Given** 비구성원, **When** 다른 환자의 기록·파일·작업을 요청함, **Then** 내용이 전달되지 않는다.
6. **Given** 일반 보호자, **When** 화면을 봄, **Then** 다른 가족의 범위 이름·잠금·숨긴 항목 개수가 표시되지 않는다.

### User Story 3 - 진료 정리를 확인한 뒤 공유 (Priority: P1)

동행자는 가상 음성·메모를 정리하고 공개할 동행 내용을 확인한 뒤 공유한다.
환자 또는 전체 내용을 볼 수 있는 A는 불일치 상세와 원문을 확인한다.

**Why this priority**: 다음 보호자가 이어받을 기록을 만들며, 확인 전 내용을 자동 공개하지 않는다.

**Independent Test**: 정리 → 검토 → 공유 → 다른 가족 조회를 실행하고 혼입·실패 사례는 공유되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 가상 음성·메모·시드 처방, **When** 정리함, **Then** 진행 상태 후 범위별 정보와 쉬운 말 요약이 함께 저장되고 아직 가족에게 공유되지 않는다.
2. **Given** 저장된 검토 가능 결과, **When** 작성자 또는 범위 관리자가 자기 권한의 공유 내용을 확인하고 공유하기를 누름, **Then** 허용된 가족의 다음 조회부터 공개된다.
3. **Given** 메모와 약봉투의 복용 시간·용량이 다름, **When** 환자 또는 A가 확인함, **Then** 두 근거·차이·메모 수정·사진 재등록 안내·병원 확인 예정이 제공된다. B에게 불일치 상세와 근거는 없다.
4. **Given** 낮은 범위용 문장에 진단명·검사 수치·변경 사유가 섞임, **When** 정리 결과를 검증함, **Then** 해당 항목을 확인 대상으로 표시하고 공유를 보류한다.
5. **Given** 일반적인 근거 누락·미해결 불일치, **When** 허용된 내용을 확인해 공유함, **Then** 값을 지어내지 않고 확인 필요를 유지한다. 민감 정보 혼입 보류는 공유 버튼으로 우회할 수 없다.
6. **Given** 정리 실패·중복 요청·입력 수정, **When** 다시 처리함, **Then** 허위 완료·중복 공유가 없고 이전 결과의 갱신 필요 여부를 표시한다.

### User Story 4 - 접근성 설정과 정적 병원 안내 (Priority: P1)

환자와 가족은 글씨 크기·고대비를 조절하고 병원 위치·정적 약도를 확인한다.

**Why this priority**: 모든 사용자가 핵심 화면을 읽고 조작할 수 있어야 한다.

**Independent Test**: 가장 큰 글씨·고대비로 1단계 화면을 순회하고 위치·약도를 확인한다.

**Acceptance Scenarios**:

1. **Given** 아주 큰 글씨와 고대비 설정, **When** 화면을 이동하거나 같은 브라우저로 재접속함, **Then** 설정이 유지되고 주요 내용·버튼이 잘리거나 겹치지 않는다.
2. **Given** 고대비 화면, **When** 화면을 봄, **Then** 흰 배경·검은 글자·진한 청록 강조·두꺼운 검은 테두리로 표시된다.
3. **Given** 병원 안내, **When** 위치·약도를 열음, **Then** 위치·주소·전화·정적 안내 순서와 가상 참고 메모가 보이고 길찾기·경로 계산은 없다.

### User Story 5 - 선택적 2단계 보강 (Priority: P2)

1단계 완주 후 환자는 비공개 메모와 위임을 관리하고, 동행자는 직접 녹음·문서 입력 등을 사용한다.

**Why this priority**: 핵심 두 시연 경로를 완주한 뒤 필요한 기능만 보강한다.

**Independent Test**: 각각의 기능을 별도로 도입하고 환자·A·B의 접근과 수정 상태를 검증한다.

**Acceptance Scenarios**:

1. **Given** 비공개 메모, **When** A 또는 B가 접근함, **Then** 거부되고 가족용 AI 입력에서도 제외된다. 환자가 선택한 메모만 의사용 화면에 포함된다.
2. **Given** 위임 설정, **When** 환자가 켜거나 끔, **Then** A의 범위 변경 권한이 다음 요청부터 바뀐다.
3. **Given** 직접 녹음, **When** 녹음함, **Then** 환자의 허용 설정을 따르고 문구·경과 시간으로 녹음 중임을 지속 표시한다.
4. **Given** 흐린 문서, **When** 판독·수정함, **Then** 원본·근거·빈 값·수정 이력을 저장하고 수정률 평가에 사용할 수 있다.
5. **Given** 공유 중단, **When** 환자 또는 위임된 A가 실행함, **Then** 해당 가족의 다음 조회가 거부되고 중단 기록이 남는다.
6. **Given** 쉬운 요약 전용 화면, **When** 열음, **Then** 이미 저장된 쉬운 요약을 표시하고 추가 AI 호출이 없다.
7. **Given** 방문 경험 입력, **When** 저장함, **Then** 공개 자료에 이름·진료 내용·사용자 식별자가 포함되지 않는다.
8. **Given** 흐름 보기, **When** 같은 과의 기록을 묶음, **Then** 결정·관찰·확인 예정으로만 연결하고 의학적으로 해석하지 않는다.

### User Story 6 - 동의·공유 고지 화면 시연 (Priority: P3)

첫 사용과 가족 초대의 고지·동의 흐름을 화면으로 설명한다. 실제 동의 시스템 완성을 주장하지 않는다.

**Why this priority**: 최종 기획안에 추가된 화면을 제시하되 가상 데모의 범위를 지킨다.

**Independent Test**: 화면에서 민감정보 별도 동의·수집 이용 동의·가족별 고지·법정대리인 경로를 확인한다.

**Acceptance Scenarios**:

1. **Given** 첫 사용 예시 화면, **When** 고지를 확인함, **Then** 두 별도 동의·전문 보기·미확정 보유 기간·거부권과 미성년자 경로를 설명한다.
2. **Given** 가족 초대 예시 화면, **When** 세 범위 중 선택함, **Then** 항목·받는 사람·목적·기간·거부권을 보여주고 실제 가족 연결은 수행하지 않는다.

### Edge Cases

- 기록·근거·진료과가 없으면 임의 맥락을 만들지 않는다. 근거 없는 값은 빈 값과 확인 필요로 남긴다.
- 근거 위치·인용·음성·문서는 모두 전체 내용 전용이다. 별도 경로·오류·다운로드로 우회할 수 없어야 한다.
- 낮은 범위의 자유 텍스트에 민감한 정보가 섞일 수 있다. 알려진 값 혼입 검사와 재서술 사례 평가를 수행하되 완전 차단을 보장하지 않는다.
- 약 이름으로 진단이 추론되는 한계는 남는다. MVP는 약 이름 표시를 유지하고 판단 결과를 추가하지 않는다.
- 질문·작업·알림·관찰·홈의 개수도 동일 범위 규칙을 따른다. 질문 답변과 원본 관찰은 전체 내용 전용이다.
- 범위 변경·공유 요청에서 요청자가 보낸 범위를 권한의 근거로 신뢰하지 않는다.
- 공개 대기 결과는 작성자·관리자만 자기 범위에서 확인한다. 다른 가족은 마지막 공유본 또는 일정만 본다.
- 원본 수정 후 공유 확정 전까지 기존 공유본을 보존하고 새 검토본을 자동 공개하지 않는다.
- 저장된 대체 결과도 같은 검증을 거치고 시연 화면에 대체 사용임을 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 환자·A·B·C의 시드 계정으로 로그인하고 연결된 환자의 기록을 선택할 수 있어야 한다.
- **FR-002**: 같은 환자·같은 진료과 기록만으로 질문 통합·브리핑·기록 비교를 수행해야 한다.
- **FR-003**: 질문을 개별 등록하고 원 질문 관계·작성자를 보존해 통합해야 한다.
- **FR-004**: 진료과 미확인 기록과 비공개 메모를 가족용 AI 입력에 넣어서는 안 된다.
- **FR-005**: 기록을 정리할 때 일정·동행·전체 내용의 비중복 정보를 함께 생성·저장해야 한다.
- **FR-006**: 조회·화면 이동·범위 변경 때문에 AI를 다시 호출해서는 안 된다.
- **FR-007**: 호출자·환자 관계·작업 권한을 확인한 뒤 허용된 정보만 읽고 응답해야 한다. 미허용 정보 묶음의 키도 응답에 없어야 한다.
- **FR-008**: 새 항목은 기본 전체 내용 전용이고, 낮은 범위는 명시적으로 허용한 항목만 제공해야 한다.
- **FR-009**: 원문·인용·근거 위치·변경 이유·의사 주요 설명·질문 답변·진단명·검사 수치는 전체 내용 전용이어야 한다.
- **FR-010**: 저장 시 모든 사실의 근거와 확인 필요 여부를 연결하고, 근거 없는 값은 비워야 한다. 낮은 범위에는 근거 위치 대신 항목 식별자·확인 필요 상태만 제공한다.
- **FR-011**: 진단·처방 결정·수치 해석·치료 권고를 생성해서는 안 된다.
- **FR-012**: 쉬운 말 요약은 진료 정리와 함께 1단계에서 생성하고 낮은 범위의 금지 정보를 포함해서는 안 된다.
- **FR-013**: 저장 전 낮은 범위 문장에 전체 내용의 진단명·검사 수치·변경 사유가 섞였는지 검사하고 탐지 시 공유를 보류해야 한다.
- **FR-014**: 정리 완료 후 검토 상태로 두고 작성자 또는 범위 관리자가 공유하기로 확정해야만 가족에게 공개해야 한다.
- **FR-015**: 검증 실패·민감 정보 혼입·오래된 입력 버전의 결과는 공유 요청으로 우회 공개할 수 없어야 한다.
- **FR-016**: 공유 시작과 범위 변경의 대상·이전값·새값·변경자·시각을 기록하고 환자 또는 위임된 대표만 조회해야 한다.
- **FR-017**: 일정만·동행·전체 내용의 범위와 공통 정보는 아래 허용표를 따라야 한다.
- **FR-018**: 범위 변경은 환자 또는 위임이 켜진 대표만 수행하고 일반 보호자의 변경은 거부해야 한다.
- **FR-019**: 일반 보호자에게 다른 가족의 범위·잠금·숨긴 개수를 표시하거나 전달해서는 안 된다.
- **FR-020**: 비구성원은 환자의 데이터·파일·작업 결과에 접근할 수 없어야 한다.
- **FR-021**: 1단계 음성 입력은 준비한 가상 파일 변환과 메모다. 실패 시 준비된 전사 대체본을 구분해서 사용해야 한다.
- **FR-022**: 오래 걸리는 작업은 진행·완료·실패를 구분하고 재시도할 수 있어야 한다.
- **FR-023**: 불일치는 코드로 비교하고 두 근거와 차이를 전체 내용 범위에 제공하되 정답을 자동 선택해서는 안 된다.

- **FR-029**: 2단계 비공개 메모는 환자만 접근하고 선택된 내용만 의사용 화면에 넣어야 한다.
- **FR-030**: 2단계 직접 녹음은 환자 허용 설정과 녹음 중 문구·경과 시간을 따라야 한다.
- **FR-031**: 2단계 문서 판독은 근거·낮은 확신도·직접 수정·원본·수정 이력을 보존해야 한다.
- **FR-032**: 2단계 공유 중단은 다음 조회를 거부하고 중단 기록을 남겨야 한다.
- **FR-033**: 동의·초대 화면은 화면 시연으로 제공하고 실제 동의·법률 검증·가족 연결 완료로 표시해서는 안 된다.

- **FR-035**: 2단계 방문 경험 공개에는 이름·진료 내용·사용자 식별자를 포함해서는 안 된다.
- **FR-036**: 2단계 흐름 보기는 같은 과 기록의 결정·관찰·확인 예정만 연결하고 의학적 판단을 추가해서는 안 된다.

## Assumptions

- 최신 근거는 `docs/baton_planning_최종.md`다. 이전 기획안은 역사 자료로 보존한다.
- 사용자 선택: 서버·저장은 로컬에서 실행하고 AI는 외부 서비스를 사용한다. 상세 기술은 plan에 기록하며 배포하지 않는다.
- 사용자 선택: 정리 결과 확인 후 공유하기로 확정. 기존 자동 공유 기본안은 폐기한다.
- 최종 기획안의 등급별 저장과 필드 배치 제안을 이번 MVP 설계 기준으로 채택하되 과거 합의 상태를 바꾸지 않는다.
- 동행의 watch/prep·불일치·관찰 상세는 아직 미정이므로 전체 내용에 둔다. 공개 범위 확대는 명시적 결정 후 반영한다.
- 원문 인용은 동행에게 제공하지 않는다. 근거 부족 표시는 낮은 범위에도 있으나 원문 위치는 숨긴다.
- 시드는 환자+A(full, 대표)+B(companion, 일반)+C(schedule, 일반)의 4계정과 B 첫 동행으로 통일한다. 위임 기본은 꺼짐이며 1단계 범위 변경 시연은 환자가 수행한다.
- 가족 관찰은 1단계 시드로 고정한다. B는 브리핑·정리를 시연하고 19번 불일치 상세는 환자 또는 A로 전환해서 시연한다.
- 공유는 작성자 또는 환자·위임 대표가 자기 권한에서 검토 후 확정한다. 권한 밖 원문은 작성자여도 열 수 없다.
- 고지·동의 화면과 보유 기간은 가상 예시다. 실제 법률·동의 체계의 완성은 범위 밖이다.
- 로컬 네트워크와 AWS 호출 연결을 전제로 하고 실패 시 저장된 가상 결과를 같은 검증 경로로 사용한다.
- 기술·모델·저장 방식은 구현 계획에 두며 이번 요청에서는 애플리케이션 코드를 작성하지 않는다.
- 권한·정보 묶음·근거·공유 상태·호출 횟수와 두 시연 경로의 자동 검증 작업을 구현 목록에 포함한다.
- 2026-10-09 명세 보완 기본안(팀 검토 전): 진료 전 질문 통합·브리핑은 검증 통과 시 공유 단계 없이 허용 범위로 보이고, '검토 후 공유'는 진료 후 정리에만 적용한다. 시연 기준일은 2026-03-12다. 세부 형태와 근거는 contracts/schemas.md·seed-story.md·docs/decisions.md에 둔다.
