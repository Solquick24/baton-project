# 바통 커밋 컨벤션

팀이 확정한 아래 타입과 의미를 사용한다. 확정되지 않은 사항을 결정의 근거로 사용하지 않는다.

## 메시지 형식

```text
Type: 변경 내용
```

타입은 아래 표의 대소문자를 그대로 사용한다.

## 커밋 타입

| 타입 | 의미 |
|---|---|
| Feat | 새로운 기능 추가 |
| Fix | 버그 수정 |
| Docs | 문서 수정 |
| Style | 코드 포맷팅, 세미콜론 누락 수정 등 코드 동작 변경이 없는 경우 |
| Refactor | 코드 리팩터링 |
| Test | 테스트 코드, 리팩터링 테스트 코드 추가 |
| Chore | 빌드 업무 수정, 패키지 관련 작업 |
| Design | CSS 등 사용자 UI 디자인 변경 |
| Rename | 파일명 또는 폴더명 수정 |
| Remove | 코드 또는 파일 삭제 |
| Add | 코드, 테스트, 예제, 문서 등의 추가 생성 |
| Improve | 호환성, 검증 기능, 접근성 등의 향상 |
| Move | 코드 이동 |

## 작성 예시

```text
Feat: 진료 전 브리핑 조회 기능 추가
Fix: 일정만 응답에 질문 개수가 노출되는 오류 수정
Docs: 팀 커밋 컨벤션 반영
Style: API 핸들러 들여쓰기 정리
Refactor: 브리핑 조회 코드 구조 정리
Test: 공개 범위별 응답 검증 테스트 추가
Chore: 패키지와 빌드 설정 수정
Design: 진료 카드 색상과 여백 변경
Rename: 브리핑 화면 파일명 변경
Remove: 사용하지 않는 코드 삭제
Add: 가상 진료 예제 파일 생성
Improve: 큰 글씨 화면의 접근성 개선
Move: 공통 검증 코드 위치 이동
```

예시는 메시지 작성법이며 해당 기능의 구현 완료나 제품 결정의 근거가 아니다.
