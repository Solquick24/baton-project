## 개발 규정

가이드 3쪽은 개발용 AI 코딩 도구를 Codex로 제한한다. 일반 IDE·터미널·컴파일러·패키지·DB·Git/GitHub·클라우드·빌드·테스트·배포 도구는 사용할 수 있지만, 이들에 포함된 다른 AI 코딩 보조 기능은 사용하면 안 된다. 계정 공유·대리 개발·팀 외 인력의 코드 작성도 참가 무효 또는 심사 제외 사유가 될 수 있다.

행사 시작 시 코드와 기존 커밋 이력이 없는 새 GitHub 저장소를 등록하고 기본 브랜치를 `main`으로 설정한다. 사전 코드·자료·기존 프로젝트는 사용할 수 있으나, 가져온 부분과 당일 새로 구현·개선한 부분을 제출 자료에서 구분해야 한다. 등록한 저장소를 계속 사용하며 커밋 이력을 삭제하거나 재작성하지 않는다. 외부 라이브러리·템플릿·데이터셋·모델의 출처와 활용 범위도 공개한다.

바통의 가져온 작업은 [사전 작업 공개 내역](prework-disclosure.md), 저장소 이전 방법은 [마이그레이션 기록](repository-migration.md)에 기록한다.

## 제출 마감과 제출물

가이드 1·2·4쪽의 마감은 **2026-10-09 17:00 KST**다. 플랫폼 제출 완료와 GitHub 서버의 `main` 최종 반영을 모두 마쳐야 한다. PC의 commit 시각이나 feature 브랜치 push만으로는 인정되지 않는다. 일정이 지연되어도 마감은 자동 연장되지 않는다.

| 제출물 | 준비 사항 |
|---|---|
| GitHub 저장소 URL | AWS 세션 후 먼저 등록. 기본 브랜치 main과 운영진 열람 권한 확인 |
| 발표 PDF | 운영진이 1차 발표에 그대로 사용하므로 최종본 제출, 로컬 사본 보관 |
| 데모·참고 링크 | 운영진 접근 가능 여부 확인, 네트워크 장애에 대비한 녹화 데모 준비 |
| Codex 기록 ZIP | 팀원별 로그를 함께 압축, 비밀 키·개인정보·회사 기밀 점검 |

팀별 6자리 키로 접속하고 플랫폼의 팀명을 확인한다. 플랫폼 주소·로그 내보내기·파일 제한과 private 저장소 열람 계정은 팀장에게 전달되는 안내를 따른다. 17:00 이후 URL·파일 등록이나 교체, 지각 제출은 허용되지 않는다. 17:00–17:10은 운영진 점검 시간이며 추가 개발·제출·자료 교체 시간으로 사용하지 않는다.
