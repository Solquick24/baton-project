# 바통(Baton) 제품 요구사항 문서 (PRD)

**제품명**: 바통(Baton) — 진료 동행 노트

**한 줄 소개**: 가족이 번갈아 동행해도 지난 진료의 맥락을 다음 동행자에게 이어준다.

**버전·기준일**: v1.0 · 2026-10-09

**상태**: 기획 기준 문서. 구현·검증 결과는 아직 없다.

**대상 범위**: 4명·약 5시간의 해커톤 당일 구현과 가상 데이터 로컬 시연

**팀·트랙**: 페이스메이커 / 충남대 · Track 2, AI for Human Life

## 2. 해결하려는 문제

반복 진료에서는 의사의 설명, 복약 변경, 다음 일정과 가족이 관찰한 변화가 서로 다른 곳에 남는다.
기억, 종이 안내문, 녹음과 가족 메시지에 흩어진 정보를 다음 동행자가 다시 모아야 한다.
지난번 동행한 사람이 아니면 무엇이 바뀌었고 이번에 무엇을 물어봐야 하는지 파악하기 어렵다.

제출안은 다음 세 상황을 문제 사례로 제시한다.

| 상황 | 사용자에게 생기는 어려움 | 바통의 대응 |
|---|---|---|
| 동행자가 약 변경을 잘못 이해해 메모함 | 꼼꼼히 공유해도 오류가 그대로 전달됨 | 기록의 차이와 근거를 보여주고 사람이 확인하게 함 |
| 집에서 변화를 본 가족이 진료에 동행하지 못함 | 중요한 관찰이나 질문이 진료실에 도달하지 않음 | 가족 질문을 모아 다음 동행자의 브리핑으로 전달 |
| 환자가 가족 앞에서 말하기 어려운 내용이 있음 | 도움을 위한 동행이 환자의 정보 통제를 제한함 | 가족별 공개 범위, 선택 단계의 비공개 메모 제공 |

지난 동행자에게 정보를 계속 물어봐야 하면 동행 부담도 같은 사람에게 집중될 수 있다.
바통은 이 전달 부담을 줄여 가족이 진료 동행을 나누도록 돕는다.
이 배경은 제출안의 사례와 제품 가설이다. 현재 사용자 조사나 부담 감소 효과를 측정한 결과는 없다.

## 3. 대상 사용자와 필요

대상은 보호자 동행이 필요한 환자 전반과 번갈아 동행하는 가족이다.
특정 연령에 한정하지 않으며, 사용자 문구는 ‘환자·보호자’로 통일한다.
한 사용자가 자기 기록의 환자이면서 다른 환자의 보호자일 수도 있다.

| 사용자 | 제품에서 이루려는 일 | MVP에서 제공하는 경험 |
|---|---|---|
| 환자, 기록 주인 | 누가 무엇을 볼지 직접 정하고 자기 기록을 이해하기 | 전체 기록, 가족별 범위 변경, 공유 기록, 쉬운 말 요약 |
| 대표 보호자 A | 지난 기록을 검토하고 가족의 동행을 돕기 | 전체 내용·원문·불일치 상세 열람. 범위 대행은 위임이 켜졌을 때만 가능 |
| 이번에 처음 동행하는 B | 짧은 시간 안에 지난 변화와 질문을 이어받기 | 동행 범위의 브리핑, 질문, 복약 변경, 쉬운 요약, 허용 내용 검토 후 공유 |
| 일정만 받는 가족 C | 방문 일정과 동행 정보를 확인하기 | 날짜·진료과·병원·동행자와 허용된 일정 |

역할과 열람 범위는 별도다. 전체 내용을 볼 수 있어도 가족의 공개 범위를 바꿀 권한이 자동으로 생기지 않는다.
시드 기본안은 환자+A(full)+B(companion)+C(schedule)의 4계정이며, A의 위임은 꺼져 있다.
1단계 범위 변경 시연은 환자가 수행한다. 실제 가입·가족 연결은 구현하지 않는다.

## 4. 제품 목표

| 목표 | 사용자가 체감해야 하는 결과 | 이번 MVP에서 확인할 증거 |
|---|---|---|
| 다음 동행자가 진료 맥락을 이어받음 | 지난 진료에 가지 않았어도 변화와 질문을 파악함 | B의 30초 브리핑과 다음 기록으로 이어지는 시연 |
| 잘못 전달된 정보의 확인을 도움 | 다른 기록을 비교하고 확인 전에는 확정 사실로 받아들이지 않음 | 시드 불일치, 두 근거, 확인 필요 상태 유지 |
| 환자가 공유를 통제함 | 가족마다 보여줄 내용이 다르고 설정 변경이 반영됨 | 세 범위 응답·화면, 범위 변경 기록, 권한 없는 변경 거부 |
| 누구나 핵심 내용을 읽고 조작함 | 큰 글씨와 고대비에서도 주요 흐름을 사용할 수 있음 | 최대 글씨·고대비로 전체 1단계 화면 점검 |

장기 제품 가설은 인수인계 준비 시간, 반복 질문과 동행 부담이 줄어드는 것이다.
이번에는 가상 시나리오로 핵심 경험을 검증하며, 의료 결과 개선이나 실제 사용자 효과를 주장하지 않는다.

## 5. 구현 범위와 우선순위

### 5.1 1단계 필수 — 핵심 사이클

| 기능 묶음 | 제공할 행동·결과 | 연결 명세 |
|---|---|---|
| 로그인·기록 선택·홈 | 4계정으로 로그인하고 허용된 환자·일정·기록을 확인 | FR-001, FR-007, FR-017~020 |
| 가족 질문·브리핑 | 질문 등록·통합, 기록 기반 추가 질문, 같은 진료과의 변화 확인 | FR-002~004, FR-010~011 |
| 진료 입력·정리 | 준비한 가상 음성 파일 변환과 메모로 정리, 쉬운 요약 함께 생성 | FR-005, FR-012~013, FR-021~022 |
| 처방 비교·정보 확인 | 시드 처방·가족 메모의 차이를 표시하고 수정·확인 예정 상태 관리 | FR-023~025 |
| 검토 후 공유·타임라인 | 검토본을 확인해 공유하고 가족이 허용된 기록만 이어받음 | FR-006~009, FR-014~017 |
| 공개 범위·공유 기록 | 환자가 세 범위를 변경하고 변경·공유 시작 이력 확인 | FR-016~020 |
| 접근성·정적 병원 안내 | 글씨 크기 3단계·고대비, 병원 위치·주소·전화·정적 약도 | FR-026~028 |

가족 관찰과 약봉투 값은 1단계에서 시드로 고정한다.
쉬운 말 요약은 1단계 정리에서 생성·저장하고 동행 기록에 표시한다. 별도 요약 전용 화면은 2단계다.
진료 입력은 준비 파일과 메모가 우선이며 앱 직접 녹음·사진 촬영은 2단계다.

### 5.2 핵심 완주 후 선택 — 2단계

직접 녹음·질문 체크 저장, 문서 사진 판독·수정, 환자 비공개 메모·의사용 화면,
대표 보호자 위임 설정, 가족별 공유 중단, 익명 방문 경험 입력, 같은 과 기록의 흐름 보기,
쉬운 요약 전용 화면은 사람이 명시적으로 요청한 경우에만 필요한 순서로 추가한다(Tier C).
선택 기능을 생략해도 1단계의 완료 기준은 바뀌지 않는다.

### 5.3 정적·화면 시연·제외 항목

| 구분 | 범위 |
|---|---|
| 정적 제공 | 가상 병원 1곳의 위치·약도·안내 순서, 참고용 더미 경험 메모 |
| 화면만, 후순위 | 민감정보 동의·가족 초대·가입·비밀번호 찾기·일정 등록, 환자 홈 예시, 알림·언어·해외 진료 방향 |
| 구현 제외 | 배포, 길찾기·원내 경로 계산·가는 법 안내·돋보기, 녹음 동의 확인 화면, 실시간 자막, 병원 시스템 연동, 제3자 역할 |

화면 시연 항목에는 실제 등록·초대·동의 완료를 표시하지 않는다.
동의 문구와 보유 기간은 예시이며, 실정보 운영 준비는 이번 범위에 포함되지 않는다.

## 6. 핵심 사용자 여정

### 6.1 다음 동행자가 이어받고 기록을 남김

1. B가 로그인하고 연결된 환자의 3월 내과 진료를 선택한다.
2. 브리핑에서 1·2월 내과 기록 이후 바뀐 점과 통합 질문을 확인한다. 정형외과 기록은 맥락에 섞이지 않는다.
3. 병원 위치·정적 약도를 보고, 준비한 가상 음성을 올리거나 메모를 남긴다.
4. 정리 진행·완료 상태를 확인하고 자기 범위의 복약 변경·쉬운 요약·일정을 검토한다.
5. 공유할 수 있는 상태이면 ‘공유하기’를 누른다. 다른 가족의 다음 조회에서 새 공유본이 보인다.
6. 불일치 상세·두 원문은 환자 또는 A 계정으로 전환해 확인한다. B에게 이 상세나 원문은 제공하지 않는다.
7. 타임라인에 공유본이 남고, 미해결 확인 항목은 다음 진료 브리핑으로 이어진다.

### 6.2 환자가 가족별 공개를 바꿈

1. 환자가 공개 범위 관리 화면에서 B의 범위를 변경한다.
2. B가 다음 조회를 하면 허용된 내용만 보이며, 조회에 AI를 다시 호출하지 않는다.
3. 환자는 대상·이전 범위·새 범위·변경자·시각을 기록에서 확인한다.
4. B가 같은 범위 변경을 직접 요청하면 서버가 거부한다. C 화면에는 일정만 제공된다.

두 경로를 우선 완주한다. 일부 화면을 시드로 보여주면 실제 동작과 시드 표시를 구분한다.

## 7. 공개 범위와 정보 통제

| 정보 | 일정만 (`schedule`) | 동행 (`companion`) | 전체 내용 (`full`) |
|---|---|---|---|
| 날짜·진료과·병원·동행자·허용 일정 | 제공 | 제공 | 제공 |
| 약·용량 변경과 주의사항, 쉬운 요약, 바뀐 점, 질문 리스트 | 제외 | 제공 | 제공 |
| 변경 이유·의사 설명·질문 답변·진단명·검사 수치 | 제외 | 제외 | 제공 |
| 원문·녹음·문서·인용·근거 위치 | 제외 | 제외 | 제공 |
| 지켜볼 증상·검사·준비사항·불일치 상세·원본 관찰 | 제외 | 제외, MVP 기본안 | 제공 |
| 비공개 메모, 2단계 | 제외 | 제외 | 환자 본인만 |

서버는 인증된 사용자와 현재 환자 관계를 확인하고 허용된 정보 묶음만 읽어 반환한다.
화면에서 숨기는 것만으로 권한을 보장하지 않는다. 원문·다운로드·질문·홈·작업 결과에도 같은 정책을 적용한다.
일반 보호자에게 다른 가족의 범위 이름, 잠금 표시, ‘숨긴 항목 N개’ 같은 정보도 제공하지 않는다.
새 항목은 전체 내용에 두고, 낮은 범위에는 명시적으로 허용한 내용만 제공한다.

원문 확인은 전체 내용 권한에서만 가능하다. 낮은 범위에는 항목 식별자와 ‘확인 필요’ 상태를 제공하고 원문 위치는 전달하지 않는다.
작성자라도 현재 열람 범위 밖 자료에는 접근할 수 없다.
2단계 비공개 메모는 대표 보호자도 볼 수 없으며 가족용 AI 입력에서 제외한다.
환자가 선택한 메모만 본인 전용 의사용 화면에 포함한다.

## 8. AI가 하는 일과 확인 규칙

AI는 질문 통합, 같은 과 브리핑, 전사·기록 추출, 쉬운 말 요약과 기록 연결을 돕는다.
진단·처방 결정·검사 수치 해석·치료 권고를 생성하지 않는다.
과거 기록에 없는 답변이나 준비사항은 지어내지 않고 빈 값과 ‘확인 필요’로 남긴다.

각 사실 항목의 근거와 확인 상태를 내부에 저장하고, 전체 내용 사용자가 원문으로 돌아갈 수 있게 한다.
불일치는 추출된 약·복용 시간·용량 등을 코드로 비교해 두 기록의 차이를 보여준다.
어느 기록이 옳은지는 자동으로 정하지 않는다. 미해결 상태는 이후에도 유지한다.

정리 시 일정·동행·전체 내용의 정보를 구분해 함께 저장한다.
동행용 쉬운 요약에는 진단명·검사 수치·변경 이유를 넣지 않는다.
저장 전에 금지 정보 혼입을 검사하고, 탐지하면 공유를 보류한다.
모델 출력은 서버에서 검증하며 프롬프트나 JSON 형식 유도만으로 정확성·범위 준수를 보장하지 않는다.

조회·화면 이동·공개 범위 변경은 저장 결과를 사용하고 AI를 다시 호출하지 않는다.
입력이 바뀌면 기존 결과가 최신인 것처럼 보이지 않게 하고 새 검토본을 만든다.
표현을 바꾼 민감 정보와 약 이름에서의 진단 추론은 문자열 검사만으로 막기 어렵다.
이번 기본안은 동행 범위의 약 이름 표시를 유지하고 이 한계를 평가에 기록한다.

## 9. 정리·검토·공유 상태와 실패 경험

| 상태·상황 | 사용자에게 보여줄 것 | 공유 동작 |
|---|---|---|
| 처리 대기·진행 | 진행 상태, 완료를 기다리는 안내 | 새 결과는 공개하지 않음 |
| 검토 가능 | 자기 범위의 결과와 확인 필요 표시 | 작성자 또는 범위 관리자가 검토 후 확정 |
| 근거 누락·미해결 일반 불일치 | 빈 값·확인 필요, 권한 있는 사용자의 상세 확인 | 허용 내용 검토 후 공유 가능, 확인 필요는 유지 |
| 민감 정보 혼입·검증 실패 | 공유 보류 또는 처리 실패, 수정·재시도 안내 | 공유 버튼으로 우회할 수 없음 |
| 입력 수정으로 결과가 오래됨 | 갱신 필요 표시, 재정리 안내 | 오래된 검토본의 신규 공유 거부 |
| 외부 AI·전사 실패 | 실패와 재시도, 대체 결과를 쓰면 그 사실 표시 | 검증된 대체 결과만 동일한 검토 과정에 사용 |
| 이미 공유된 기록을 재처리 | 기존 공유본과 새 검토본의 상태 구분 | 새 확정 전까지 기존 공유본 보존 |

공유 전 검토본은 작성자·범위 관리자가 자기 범위 안에서만 확인한다.
다른 가족은 마지막 공유본 또는 허용된 일정만 본다.
중복 처리·반복 공유 요청으로 기록이 중복되거나 완료가 허위 표시되지 않아야 한다.

## 10. 화면·접근성 요구

모바일 우선 웹앱으로 구성하며 홈·타임라인·설정의 하단 탭을 사용한다.
모바일 390px 와이어프레임을 기준으로 핵심 동작과 상태를 읽기 쉽게 표현한다.
글씨 크기는 3단계로 제공하고 같은 브라우저에서 설정을 유지한다.
고대비는 흰 배경·검은 글자·진한 청록 강조·두꺼운 검은 테두리를 적용한다.
가장 큰 글씨에서도 내용과 주요 버튼이 잘리거나 겹치지 않아야 한다.

쉬운 말 요약은 의미를 지어내거나 약 이름·용량·일정을 바꾸지 않는다.
상태는 색상만으로 전달하지 않는다. 2단계 직접 녹음은 환자의 허용 설정을 따르고 ‘녹음 중’ 문구와 경과 시간을 계속 표시한다.
병원 약도와 더미 방문 경험은 참고 자료로 표현하며 실제 경로 계산이나 공식 의료 판단을 제공하지 않는다.

## 11. 성공 지표와 완료 기준

아래 수치는 기존 spec의 가상 MVP 검증 목표다. 아직 측정된 결과는 없으며 적용 범위는 준비한 검증 사례다.

| 기준 | 검증 목표 | 명세 기준 |
|---|---|---|

| 근거·확인 상태 | 시드 사실 항목 100%에 내부 근거 또는 빈 값·확인 필요가 있음 | SC-002 |
| 범위 보장 | 역할별 조회·원문·질문·알림·작업 결과에서 금지 정보 전달 0건 | SC-003 |
| 저장 결과 재사용 | 반복 조회 10회·범위 변경 3회에서 추가 AI 호출 0회 | SC-004 |
| 공유 통제 | 진료 후 정리의 확정 전 공개·혼입 보류 우회·중복 공유 0건 | SC-005 |
| 불일치 유지 | 전체 내용 계정이 차이를 확인하고 미해결 상태가 이후에도 유지됨 | SC-006 |

누출 평가는 혼입 검사 전후와 표현 변형 사례를 나눠 기록한다.
실제 사용자 만족도나 의료 효과의 수치 목표는 현 단계에서 추가하지 않는다.
구현 완료는 문서 작성이나 화면 존재만으로 판단하지 않고 해당 수용 기준의 검증 결과로 기록한다.

## 12. 실행 환경·자료·의존성

실행 환경은 React/Vite 프론트와 로컬 Fastify API, SQLite 저장, 시드 로그인이다.
AI는 AWS Bedrock·Transcribe를 사용한다. 구체 버전·모델·계약은 plan과 [설계 조사](../specs/001-baton-mvp/research.md)에 둔다.
앱을 배포하거나 새 AWS 서버리스 인프라를 구성하지 않는다.
배치 전사에는 기존 제공 S3 버킷을 임시 경유하고 앱의 영구 기록은 로컬에 저장한다.
계정 접근·제공 버킷·실제 호출 성공은 구현 시작 시 확인할 의존성이다.

시연 자료는 가상 환자 1명, 내과 1·2월 기록과 3월 예정 진료, 정형외과 비교 기록,
가족 질문 3개, 관찰·불일치 시드, 가상 병원·음성·문서·정답 라벨로 구성한다.
현재 준비된 자료는 시드·AI 응답·혼입 샘플·기대값 JSON 16개와 녹음 대본이다.
테스트 비구성원 1계정이 추가됐으며 실제 음성 파일·약 20장 모의 문서는 아직 없다.
T065 축소 평가는 fixture 4건·불일치 1건의 실제 분모를 기록하고 SC-009 전체 문서 평가 목표와 구분한다.
실제 호출 결과, 검증된 저장 대체 결과, 시드와 화면 시연을 명확히 구분한다.
API 키·자격 증명·실제 환경 파일·로컬 DB·업로드는 저장소와 제출 자료에 포함하지 않는다.

현재 68개 작업은 모두 미완료다. 개발 시간에 맞춰 선택 단계의 범위를 줄일 수 있으나 권한·근거·공유 검증을 생략하지 않는다.

제출안의 역할은 장현성(팀장·백엔드 설계), 김기원(AI 설계), 박종현(기획·검증), 한상균(프론트 설계)이다.
현재 plan의 API·DB·인증 / AI·검증 / 시드·데모·평가 / 프론트·접근성 분담과 연결할 수 있으며 실제 작업 배정은 팀이 조정한다.

## 14. 제출안과 현재 기준의 차이

제출안 자체의 원문은 변경하지 않으며 위 차이를 현재 제품 기준으로 구분한다.
