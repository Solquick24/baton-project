# 홈·공통 탐색 개선 — #47

## 변경 결과

최신 origin/devlop ac422ec에서 fix/47-home-navigation을 만들고 /tmp/baton-home-47에서 작업했다. 다른 세션의 공용 작업 폴더와 서버는 보존했다. 로그인 복구 [#44](https://github.com/Solquick24/baton-project/pull/44)의 병합 상태를 확인했다.

- 홈은 `박하늘님의 기록` 제목을 한 번 표시한다. 선택 대상이 한 명이면 이름 버튼을 생략하고, 여러 기록이 있으면 전환 메뉴를 유지한다. 상세 화면은 기록 주인을 짧은 문맥으로 표시한다.
- `briefingReady=true`면 브리핑 보기, `false`면 가족 질문으로 준비하기를 표시한다. 키가 없으면 준비·브리핑·기록 버튼을 만들지 않는다. 기록하기는 보조 행동으로 구분한다.
- 지난 진료의 약 변경·쉬운 요약은 펼쳐 읽는다. 받은 내용은 자르지 않으며 확인 필요는 접힌 상태에서도 표시한다. 날짜·병원·다음 일정과 full 전용 근거 표시 조건은 유지한다. 타임라인과 검토 화면은 기존 내용을 유지한다.
- 오류·잘못된 경로의 홈 링크는 현재 환자 홈으로 돌아간다. 404는 찾을 수 없다는 안내와 복귀 방법을 함께 표시하며 가족의 범위나 결과 존재를 추측하지 않는다.
- 진료 입력·검토·공유 설정·불일치 화면은 실제 작업 제목을 사용한다. 설정으로 이동해도 직전에 선택한 환자를 유지한다. 환자 ID만 현재 세션의 컴포넌트에 보관하며 계정 전환 뒤에는 초기화된다.
- 상단 바통 링크의 누르기 영역을 48px 이상으로 늘리고 다음 진료 카드의 간격·보조 버튼·키보드 초점을 정리했다.

근거는 [기존 UI/UX 검토](ui-ux-review-20261009.md), [화면](../specs/001-baton-mvp/screens.md), [응답 계약](../specs/001-baton-mvp/contracts/schemas.md), [시드](../specs/001-baton-mvp/seed-story.md)다. 사용자 제공 논문의 명확한 정보·직관적 탐색·간편한 조작을 바통에 적용했다. 이번 배치 자체가 논문의 제안이거나 사용자 인터뷰로 검증됐다고 주장하지 않는다. T026의 후속 개선이며 기존 Task 완료 체크를 변경하지 않았다.

## 실제 검증

PR #52 제출 뒤 #51의 devlop f03384c가 추가되어 충돌을 해결했다. 최신 캐릭터·온보딩·병원/녹음/저장 요약 동선·상세 화면의 고정 탭 제거를 보존했다. 아래는 통합 후 다시 실행한 결과다. 최초 ac422ec 기준의 34 E2E/14 preview 통과와 구분한다.

| `E2E_API_PORT=3107 E2E_WEB_PORT=5187 npm run test:e2e` | 실제 API E2E 41통과/0실패. 새 홈 7건, 기존/온보딩 34건 |

| `git diff --check`, 변경 문서의 상대 링크 검사 | 통과 |

브라우저는 이 환경의 별도 Chromium 라이브러리/한글 폰트 설정으로 실행했다. 새 준비/미준비/일정만/320×568 아주 큰 글씨·고대비의 캡처를 직접 확인했다. B의 390×844 브리핑 변경/질문이 첫 화면에 있고 상세 화면에는 고정 탭이 없으며, 작은 화면에서 마지막 지난 진료 조작에 초점을 옮겼을 때 하단 탭에 가리지 않음을 DOM 치수로 검사했다. 측정하지 않은 사용성 점수·완료 시간은 기록하지 않는다.

모두 로컬 fixture 모드이며 live AI·배포는 수행하지 않는다. API 구현은 변경하지 않았고 전체 API Vitest는 이번 후속 UI 작업에서 재실행하지 않았다. 실제 API를 호출하는 기존 권한·범위·공유·세션 E2E로 해당 영향 범위를 검증했다.

새 E2E의 브리핑 준비/미준비·일정만 계정·404는 실제 Fastify API와 메모리 SQLite를 사용한다. 여러 환자 선택과 완전 빈 홈은 브라우저에서 응답을 가상 변형한 UI 경계 검사이며 실제 여러 환자 DB 생성·빈 환자 API 시연으로 계산하지 않는다. 생성 전 CTA·제목 중복·복귀 경로의 재현 검사 3건은 수정 전 모두 실패했다. 처음 기본 포트로 실행할 때 다른 세션의 3101이 사용 중이어서 검사를 시작하지 못했고, 이후 3107/5187에서 실행했다. 첫 개선 검사에서는 5통과/2실패였고, 시드 약 이름의 용량 표기와 다중 환자 설정 문맥의 테스트 기대값을 교정한 뒤 전체 34건을 재실행해 통과했다.
