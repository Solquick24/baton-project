# 프론트 구현 계획

**담당 역할**: 사용자 FE 리드. 기존 MVP 계획·작업·화면·팀 PDF·계약·시드를 기준으로 한다.
계획 수립 당시 프론트와 실제 API는 없었다. 프론트를 먼저 개발하되 개발용 응답의 화면 검증과 실제 API 통합 완료를 구분한다.
팀 절차는 [branch-workflow.md](branch-workflow.md)를 따른다.

## 첫 이슈: FE-01~FE-04

실행·공통 UI부터 만든 뒤 첫 이어받기 흐름을 개발용 응답으로 확인한다. 읽기 타임라인·개인 화면 보기 설정도 함께 제공한다.
실제 API·범위 변경·진료 후 처리·AI 호출은 다음 이슈다.
개발용 응답은 Vite 개발 서버의 별도 모드에서만 제공하고 기존 API 경로·필드 형태를 따른다.
fixture는 서버 개발 코드에서 읽고 호출자에게 허용된 응답만 보낸다. full 자료·비밀번호·scope 표를 브라우저 번들에 넣지 않는다.
실제 API 모드는 localhost:3001 프록시를 사용한다. 개발용 로그인·메모리 상태는 실제 JWT·서버 권한 완료로 계산하지 않는다.
질문 통합·브리핑은 저장된 예시이며 AI 호출로 표시하지 않는다. 입력에 맞는 fixture가 없으면 실패를 표시한다.

## 첫 이슈 완료 조건

- 설치 버전을 실제 레지스트리·빌드로 확인하고 lockfile에 고정한다.
- 로그인·홈·질문·브리핑·읽기 타임라인·화면 보기 설정의 라우트를 실행할 수 있다.
- B/C에 원문 버튼·불일치 개수·등급 이름을 만들지 않고 받은 블록만 표시한다.
- 390×844 B 브리핑에서 변경 2개·질문 3개를 먼저 보여준다.
- 타입검사·빌드·브라우저 흐름·응답 금지 키/문자열·큰 글씨/고대비를 확인한다.
- 기존 T001~T029를 전체 완료로 체크하지 않는다. 실제 API·공유·인증 선행 작업은 남긴다.
- 체크포인트에서 실제 검사 결과·개발용 모드·미완료를 기록하고 devlop 대상으로 PR을 만든다.

## 진행 기록

2026-10-09: 기존 계획·화면·PDF 로그인/홈/질문/브리핑을 확인하고 첫 이슈 범위를 정리했다. 사용자 FE 리드 역할과 팀 이슈별 브랜치 절차를 기록했다.
구현·검증 결과는 첫 이슈 작업 후 추가한다.

첫 작업은 [이슈 #2](https://github.com/Solquick24/baton-project/issues/2), `feat/2-frontend-foundation` 브랜치로 진행한다.
FE-01·FE-02·FE-03의 프론트 기반과 FE-04의 조회 흐름을 구현했다. FE-04의 실제 질문 등록·생성 통합은 아직 끝나지 않았다.
서버 검증기가 없으므로 개발용 새 질문은 환자·A만 full 전용으로 저장한다. B 등록은 거부하며 입력을 유지한다. 실제 API에서 검증기를 연결한 뒤 명세의 B 등록을 완성한다.
진료 전 결과는 시드 pregenerate에 해당하는 저장된 예시로 시작한다. 변경된 입력은 같은 예시로 성공 처리하지 않는다.
`npm run dev:preview`는 프론트 개발용 실행이며 `npm run dev`는 기존 API·웹 동시 실행을 유지한다. 작업 중 병합된 Phase 1의 기존 완료 체크를 보존했고 프론트 구현만으로 추가 MVP 작업을 완료 체크하지 않았다.

### 첫 프론트 체크포인트 검증

Node 22.23.2/npm 10.9.8에서 의존성을 설치하고 `npm run build:web`(웹 타입검사 포함)가 통과했다.
개발용 모드 Playwright 14건이 통과했다. 로그인 실패, B 첫 화면 변경 2개·질문 3개, C 응답 키 부재·직접 주소 404, A 근거와 빈 준비사항, 비구성원 403, 진료과 필터, 계정 전환·401 세션 해제, 아주 큰 글씨·고대비·가로 넘침, 202 처리·폴링 종료, B 등록 거부와 입력 유지, 버전 충돌, 입력 변경 후 fixture 실패, 최신 blocked 응답과 진료과·초안 조회 규칙을 확인했다.
Linux 환경의 Playwright 1.64.0/Chromium 1248을 사용했다. 시스템에 없는 공유 라이브러리는 기존 임시 로컬 라이브러리로, 한글 글꼴은 로컬 Noto Sans KR로 보완해 검증했다. 라이브러리·글꼴은 저장소에 넣지 않았다. 일반 Linux 환경에서는 Playwright 시스템 의존성과 한글 글꼴을 먼저 설치한다.
AWS 호출은 수행하지 않았다. 개발용 어댑터 응답 검사는 실제 API JWT·DB·검증기의 권한 검증을 대체하지 않는다.

작업 중 최신 `origin/devlop`의 Phase 1 실행 기반과 이슈 #5 계약 보완을 통합했다. 기존 health 공유 스키마·API·환경 설정·실행 명령·완료 체크는 보존했다. `npm run build`로 세 workspace와 도구 타입검사·웹 빌드가 통과했고 `npm run test` API 테스트 17건, `npm run test:e2e` 실제 API health·Vite 프록시 브라우저 검사 1건도 통과했다.
웹 빌드에서 가상 비밀번호·원본 fixture 값·개발용 계정 endpoint 등 8개 표식이 없는 것을 확인했다. 읽기 DTO만 추가했으며 전체 T008 Zod 검증기와 진료 후 작업은 아직 미완료다.
