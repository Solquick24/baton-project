# 바통 UI/UX 검토 — 간결한 화면과 이어지는 사용 흐름

## 근거와 적용 범위

사용자가 제공한 임연주·김승인(2025), 「의료 플랫폼 UI/UX 설계가 접근성 향상에 미치는 영향: 굿닥, 모두닥, 강남언니를 중심으로」, *Industry Promotion Research*, 10(1), 157–162, [DOI](https://doi.org/10.21186/IPR.2025.10.1.157)를 로컬 PDF 6쪽 전체에서 확인했다.
파일 SHA-256: `51db457c4ab514308f3f35160e4a06b8bf5fd729b678efd3e2ab6969e3394026`. 논문 파일은 저장소에 복사하지 않았다.

- 159쪽: MARS와 심층 인터뷰, 20·30대 12명(플랫폼별 경험자 2명·비경험자 2명)의 정성 연구다.
- 161쪽 결론: 정보의 명확성·최신성·신뢰성, 직관적인 탐색, 간편한 조작, 심미성과 기능성의 균형을 강조한다.
- 논문이 직접 정한 버튼 개수·클릭 수·바통 화면 배치는 없다. 아래 개선안은 연구 결과를 바통에 적용한 설계 판단이다. 고령 보호자의 사용성을 검증한 연구로 해석하지 않는다.

검토는 최신 `devlop` `8318aab`와 #33의 빠른 선택 복구를 기준으로 했다. 작업 중 다른 세션의 실제 API 통합 [PR #36](https://github.com/Solquick24/baton-project/pull/36)이 병합되어 최신 화면에서 다시 확인했다. T020 [PR #31](https://github.com/Solquick24/baton-project/pull/31)의 세션과 #32의 진료 입력·검토·공유·불일치·범위 관리 화면을 보존했다. 실제 Fastify API·메모리 SQLite·fixture로 실행했고 live AI·사용자 인터뷰·MARS 점수 평가는 수행하지 않았다.

최종 제출은 이후 질문/브리핑 보완 PR #38까지 포함한 `4079dec`의 독립 checkout `/tmp/baton-33-review`에서 진행한다. 두 기준의 프론트 화면 코드는 동일하며, 다른 세션이 같은 원래 작업 폴더에서 추가 중인 병원·녹음·Tier C 초안은 이 제출에 포함하지 않는다. 제출 브랜치는 `fix/33-demo-login-review`다.

UI/UX Pro Max 스킬의 접근성·탐색·피드백 기준과 [프론트 지침](../apps/web/AGENTS.md)을 참고했다. 스킬 검색이 제안한 랜딩 페이지 패턴·영문 폰트·새 색상·입체 스타일은 이 한국어 모바일 업무 화면에 맞지 않아 채택하지 않았다. 기존 청록 브랜드·시스템 한글 폰트·단일 열·명세의 권한 계약을 유지한다.

6. 기존 실제 API 시연·권한·공유 회귀를 유지하면서 접근성·병원 안내와 최종 평가 등 남은 Tier A/B 작업을 기존 순서로 진행한다. 기능별 완료 후 보고하고 멈춘다. 이미 완료된 Task를 디자인 개선의 미완료와 혼동하지 않는다.

새 메뉴·대시보드·온보딩·꾸밈용 애니메이션은 추가하지 않는다. 공유의 명시적 확인과 full 전용 근거 확인은 간결화를 이유로 제거하지 않는다. GET·화면 이동에서 AI 생성 요청을 보내지 않으며 보호자에게 범위·잠금·숨긴 개수를 암시하지 않는다. Tier C는 요청 범위에 포함하지 않는다.

다음 흐름을 목표로 한다: **가족 기록 홈 → 오늘 질문 준비 → 진료 전 브리핑 → 진료 입력 → 내용 확인 → 명시적으로 공유**. 각 화면에서는 지금 할 일 하나를 주 행동으로, 나머지는 보조 행동으로 구분한다. 이 흐름은 논문의 직접 제안이 아니라 바통 요구사항에 맞춘 적용안이다.

## 이번 변경과 남은 검증

#33은 로그인 복구와 상단 `나` 제거만 구현한다. 위 P0/P1의 전체 리디자인은 아직 구현하지 않았다. #36의 기존 Task 완료 체크를 보존하고 새 완료 체크를 추가하지 않는다. 실제 사용자 대상 이해도·완료 시간·오조작 검증, 모바일 소프트 키보드·실제 스크린리더·실기기 safe area·live 생성 결과는 후속 검증이다.

| 실행한 검사 | 결과 |
|---|---|
| `npm run typecheck`, `npm run build:web` | 통과 |
| `npx playwright test --config apps/web/playwright.api.config.ts` | 실제 API 빠른 선택·JWT·C 제한 UI·실패 후 재시도 6건 통과 |
| `WEB_PORT=5184 npm run test:web` | preview 14건 통과. 사용 중인 5173 서버를 보존하고 별도 포트 사용 |

| 웹 배포 번들 문자열 검사 | 가상 비밀번호·계정 이메일·개발용 endpoint/fixture 경로 등 7개 표식 부재 |
