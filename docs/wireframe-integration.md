## 문서 반영과 이후 검증

screens.md에 공통 스타일·쪽 번호·화면별 배치를, plan.md에 적용 순서·검증 기준을 추가했다. tasks.md의 기존 UI·E2E 작업에 이 PDF의 참조를 연결했고, 작업 완료 체크는 변경하지 않았다. spec.md·스키마·API·시드·fixture는 변경하지 않았다.

이번 확인은 원본 해시·25쪽 연결·Markdown 링크·변경 diff의 문서 검증이다. 앱 실행·브라우저 시각 검증·E2E·AI 호출은 수행하지 않았다. 구현 후 T029·T036·T047·T051에서 다음을 확인한다.

- 390×844 보통 글씨의 B 브리핑: 바뀐 점·최종 질문 3개가 첫 화면에 들어온다. 아주 큰 글씨에서는 스크롤을 허용하고 항목을 생략하지 않는다.
- B/C 화면에는 full 섹션·원문 버튼·불일치 개수·범위 이름이 없고, 범위 변경 후 이전 화면 캐시가 남지 않는다.
- 진료 정리의 ready·blocked·failed·stale·공유 전후를 구분한다. 정리 완료만으로 공유 성공 배너를 표시하지 않는다.
- 가장 큰 글씨·고대비에서 칩·카드·하단 버튼이 잘리거나 겹치지 않고, 마지막 내용과 키보드가 주요 버튼에 가리지 않는다.
