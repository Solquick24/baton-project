# 온보딩 체크포인트 — 이슈 #41

2026-10-09 사용자 요청으로 기존 진료 동행 흐름을 설명하는 4단계 온보딩을 추가했다. 기존 tasks.md에 대응하는 작업 ID가 없어 #41로 추적하며 기존 Phase/Tier 완료 표시는 바꾸지 않는다.

## 동작과 결정

- 브라우저 첫 방문에 자동으로 모달을 연다. 바통 소개 → 진료 전 브리핑 → 음성·메모·정리 → 검토 후 공유를 글·SVG 그림·정적 화면 예시로 설명한다.
- 화면 예시에서 해당 버튼은 밝게 남기고 주변은 반투명 검정으로 처리한다. 예시는 실제 환자/가족 데이터가 아니며 원문·권한·잠금·숨긴 개수를 넣지 않는다.
- 가로 스와이프·이전/다음·단계 버튼·좌우 화살표 키로 이동한다. 건너뛰기/Escape 또는 마지막 `바통 시작하기!`로 닫으며 완료를 기억한다. 버튼은 고정된 하단 영역에, 긴 설명은 독립된 스크롤 영역에 둔다.
- 로그인·설정의 사용법 버튼으로 언제든 다시 연다. 마지막 방문에서 30일 이상 지나면 비차단 재안내 배너를 제공한다.
- `baton.onboarding` v1에는 완료/마지막 방문 시각만 저장한다. 계정·환자 데이터는 저장하지 않는다. 저장소 실패/잘못된 데이터에서도 안내를 완료하고 서비스를 이용할 수 있다. 저장소 차단 시 새로고침에 안내가 다시 열릴 수 있다.
- 기존 글씨 3단계/고대비를 그대로 사용한다. 네이티브 dialog의 배경 비활성화, 명시적 포커스 순환/복귀, 48px 이상의 조작 영역과 스와이프 대체 버튼을 제공한다.
- 온보딩은 제품 API의 생성·수정·공유 요청이나 AI 호출을 수행하지 않는다. API 계약·fixture·권한 표 변경 없음. Tier C 기능 추가 없음.
- 근거: [화면](../specs/001-baton-mvp/screens.md), [헌장](../.specify/memory/constitution.md), [FE 지침](../apps/web/AGENTS.md), [결정](decisions.md)의 #41 행.

## 실제 검증

| 명령 | 최종 결과 |
|---|---|
| `npm run typecheck` | 전체 워크스페이스 및 tools 통과 |
| `npm run build` | 전체 타입검사 + 웹 production 빌드 통과 |
| `npm run test --workspace @baton/api -- --maxWorkers=1` | API 247 통과, 0 실패(22 파일) |
| `WEB_PORT=5276 npm run test:web` | preview 21 통과, 0 실패 |
| `npm run test:e2e` | 실제 fixture API E2E 34 통과, 0 실패 |
| 현재 원본 작업 폴더의 웹 typecheck/build | 기존 미커밋 화면/브랜드 변경과 함께 통과 |
| 현재 원본 작업 폴더의 온보딩 브라우저 검사 | 7 통과, 0 실패 |

브라우저는 이미 준비된 `/tmp/baton-main-browser-libs/extracted/usr/lib/x86_64-linux-gnu`를 `LD_LIBRARY_PATH`로 사용했다. 한국어 화면 검증에는 `/tmp/baton-fe-fonts/NotoSansKR.ttf`를 읽는 임시 Fontconfig 설정을 사용했고 앱에 폰트 다운로드/패키지를 추가하지 않았다. 기존 :5173 개발 서버를 보존하기 위해 preview config가 `WEB_PORT`를 받도록 했다. 현재 작업 폴더 검사는 :5277을 사용했다.

초기 실행의 캐시 쓰기 제한, 포트 충돌, Chromium 라이브러리 누락을 해소한 뒤 검사했다. 첫 검사에서 발견한 키보드 포커스 순환을 보완하고 스와이프 테스트의 Touch 생성 오류를 수정했다. 기존 흐름 검사는 이미 안내를 본 방문을 설정하며, 별도 새 브라우저/저장소 차단에서는 안내를 먼저 닫은 뒤 로그인하도록 도우미를 고쳤다. 공유 재시도 검사 초기 실패도 최종 전체 실행에서 통과했다.

## 모드와 한계

LLM/STT는 fixture이며 preview와 실제 로컬 API를 각각 검사했다. 온보딩 자체는 정적 안내다. 외부 OpenAI/AWS 호출·실제 모바일 기기·스크린리더 사용자 검증은 미실시다. 브라우저 390×844 및 375×667/844×390, 아주 큰 글씨·고대비·reduced motion, 저장소 실패·재방문·스와이프·키보드·포커스를 검사했다. 기존 미완료 T048~T051 및 Tier C 완료 표시는 변경하지 않았다.

별도 최신 devlop 기반 worktree에서 온보딩만 커밋/PR로 분리했다. 원본 작업 폴더에도 온보딩을 적용했으며 진행 중인 다른 화면/브랜드 변경은 보존한다. PR/병합 결과는 이슈 #41과 연결 PR 본문에서 확인한다. main 반영·배포 없음.

PR 생성 중 최신 devlop ac422ec에 #43 미확인 복약 표시와 #44 빠른 로그인 수정이 병합되어 이를 보존 통합했다. 로그인 부분은 최신 구현에 사용법 버튼을 추가하고 결정 표는 양쪽 행을 보존했다. 통합 후 전체 타입/빌드·preview 21·실제 API E2E 34를 재검증했다. 동시 API 검사에서 2건이 5초 제한에 걸려 제품/시간 제한을 바꾸지 않고 작업자 1개로 전체를 재검사했다.

## 팀 공유 반영 확인

제품 코드·기존 브라우저 검사 도우미는 팀 공유 PR #51의 f03384c에 먼저 반영됐다. 이를 모두 보존 통합한 뒤 전체 typecheck와 실제 fixture API의 온보딩 7개 + 범위 변경/저장소 차단 로그인 2개를 재검사해 9 통과, 0 실패를 확인했다. 앞 표의 전체 build/API247/preview21/E2E34는 ac422ec 보존 통합 시점의 결과이며, 원본 화면과 브랜드의 온보딩 7개도 별도로 통과했다.

PR #46의 최종 devlop 대비 변경은 웹 README 링크와 이 체크포인트 문서뿐이다. 온보딩 서비스 코드는 [PR #51](https://github.com/Solquick24/baton-project/pull/51), 검증 기록은 [PR #46](https://github.com/Solquick24/baton-project/pull/46)로 추적한다. 원본 E2E에서도 첫 방문 안내를 처리하는 검증된 연결이 유지된다.
