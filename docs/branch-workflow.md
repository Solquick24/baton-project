# 바통 브랜치 작업 방식

팀이 정한 작업 흐름은 `devlop`에서 작업한 뒤 검증한 변경을 `main`에 병합하는 방식이다.
브랜치 이름은 요청한 `devlop`을 사용한다.

| 브랜치 | 역할 |
|---|---|
| `devlop` | 새 작업·수정·커밋을 진행하는 개발 브랜치 |
| `main` | `devlop`에서 검증한 변경을 병합하는 기준 브랜치 |

## 작업 순서

1. `devlop`으로 전환하고 원격의 최신 변경을 반영한다.
2. 작업한 내용에 맞는 검사를 실행하고 결과를 확인한다.
3. [커밋 컨벤션](commit-convention.md)에 따라 커밋하고 `origin/devlop`에 push한다.
4. 병합할 변경과 검사 결과를 검토한다.
5. 최신 `main`에 `devlop`의 검증한 변경을 병합하고 `origin/main`에 push한다.

코드 변경은 AGENTS.md의 해당 검증 기준을 따른다. 문서만 바뀌면 변경 내용·링크를 확인한다.
검사하지 않은 항목이나 실패한 검사는 완료 보고에 명시한다.

`main` 반영은 `devlop`에서 작업·검증한 변경의 병합으로 진행한다.
브랜치 분리는 기능 범위·Tier·권한·가상 자료 규칙을 변경하지 않는다.
